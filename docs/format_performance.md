# 真实工业相机图像格式性能测试

测试日期：2026-11-06。数据来源为项目实际运行日志和性能 CSV，非虚拟设备、非异常注入。

## 设备与方法

- 设备：MV-CS016-10UC，USB，序列号 DA4302122。
- 实际图像尺寸：1440×1080；ROI 的 OffsetX/OffsetY 尚未记录。
- 两组曝光设定和读回均为 1000 μs，增益设定和读回均为 0 dB。
- 每组处理 300 帧；不运行 YOLO，不显示窗口，达到帧数后自动退出。
- 设备原生输出分别为 BayerRG8 和 BGR8，两种设置均被接受，并由实际帧格式核对。
- 当前为各一次测量。设备帧率限制、光源及其余设备参数未由这些日志完整记录，须现场补充。

CLion“程序实参”分别为：

```text
--serial DA4302122 --exposure 1000 --gain 0 --format BayerRG8 --frames 300 --headless --no-yolo
--serial DA4302122 --exposure 1000 --gain 0 --format BGR8 --frames 300 --headless --no-yolo
```

## 说明与分析

BayerRG8 每个像素位置保存一种颜色采样，程序通过 OpenCV 去马赛克得到三通道 BGR。BGR8 的输入已有三个颜色通道，因此本次 BGR8 转换耗时为 0；为了归还 SDK 缓冲区后仍能安全使用图像，程序进行独立内存复制，其耗时单独记录。

本次 BayerRG8 的实际 FPS 更高，同时整个进程 CPU 占用也更高。BayerRG8 的 CPU 约为 563.806%，按本程序的统计口径相当于平均约 5.64 个逻辑核满载，并非整机 CPU 使用率超过 100%。BGR8 组约为 9.369%。统计包含整个进程的线程活动，不能将全部 CPU 使用量归因于去马赛克函数。

原生 BGR8 每像素三个字节，BayerRG8 每像素一个字节；传输数据量、设备内部处理、SDK 和 OpenCV 线程开销都可能影响结果。这两次测量不能单独确定各因素贡献，也不能推导原生 BGR8 在所有设备和场景中都更慢。FPS 为本程序采集处理吞吐率，不是相机标称帧率。

两组都正常达到 300 帧，借出/归还均为 300/300。运行日志均确认停止采集、关闭设备、销毁句柄和释放 SDK；未注入异常。借还计数相等和清理日志是本次资源检查证据，不等于全面内存泄漏检测。
